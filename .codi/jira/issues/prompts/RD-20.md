# RD-20: Implementar un helper Zsh que simplifique el uso del comando `herdr worktree` desde la terminal

## Contenido Fuente

### Scenario

El módulo Zsh `herdr` ubicado en `~/.dotfiles/zsh/modules/herdr/` actualmente expone helpers para gestionar workspaces (`hrd`, `hrdk`) pero no incluye wrappers para el subcomando `worktree` del binario `herdr`.

El binario `herdr` (agent multiplexer) soporta de forma nativa los siguientes subcomandos worktree:

- `herdr worktree list [--workspace ID | --cwd PATH] [--json]`
- `herdr worktree create [--workspace ID | --cwd PATH] [--branch NAME] [--base REF] [--path PATH] [--label TEXT] [--focus] [--no-focus] [--json]`
- `herdr worktree open [--workspace ID | --cwd PATH] (--path PATH | --branch NAME) [--label TEXT] [--focus] [--no-focus] [--json]`
- `herdr worktree remove --workspace ID [--force] [--json]`

Los worktrees son workspaces normales de Herdr con procedencia de Git checkout. `worktree create` crea un git worktree checkout, lo abre como workspace de Herdr, y lo agrupa con el workspace del repo padre. Por defecto los checkouts se almacenan bajo `<worktrees.directory>/<repo>/<branch-slug>`.

El helper debe integrarse con las convenciones existentes del módulo (`pkg/` para funciones públicas, `internal/` para lógica interna, selectores fzf, aliases cortos) y manejar edge cases como directorio actual sin git repo o worktree ya existente.

### Acceptance Tests

- El helper permite crear un worktree desde el directorio actual usando `herdr worktree create --cwd . --branch <name>`
- El helper permite listar worktrees existentes con estado (activo, stopped, etc.)
- El helper permite navegar y cambiar entre worktrees usando fzf
- El helper se integra con el módulo herdr existente (sigue convenciones de pkg/, internal/, sourcing chain)
- El helper es accesible desde un alias corto similar a hrd/hrdk
- El helper maneja errores (directorio no es git repo, worktree ya existe, --force requerido para dirty checkouts)
