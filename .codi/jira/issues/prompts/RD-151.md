# RD-151: Crear módulo ZSH helix siguiendo la guía create-module, tomando como referencia el módulo nvim

## Contenido Fuente

### Scenario

Como desarrollador de CodipLabs, necesito un módulo ZSH para gestionar el editor Helix en mis dotfiles, siguiendo la arquitectura de tres capas (config/internal/pkg) documentada en docs/guides/create-module.md y tomando como referencia el módulo existente zsh/modules/nvim/.

El módulo debe gestionar la instalación de Helix, la sincronización de su configuración (config.toml, languages.toml, themes/) desde data/ hacia ~/.config/helix/, y exponer comandos públicos (helix::install, helix::sync, helix::setup, etc.) siguiendo las convenciones de nomenclatura ZSH_<NAME>_ y las funciones core (message_*, core::exists, core::ensure).

Helix no tiene plugin manager (a diferencia de lazy.nvim en Neovim), por lo que el módulo se enfoca en: instalación del binario hx, sync de config.toml + languages.toml + themes/, y gestión del runtime (hx --grammar fetch/build).

### Acceptance Tests

- Scaffold completo del módulo en zsh/modules/helix/ con config/, internal/, pkg/, data/
- plugin.zsh con guard idempotente __ZSH_HELIX_LOADED y cadena config → internal → pkg
- config/base.zsh exporta ZSH_HELIX_ENABLED, ZSH_HELIX_PACKAGE_NAME, ZSH_HELIX_CONFIG_PATH, ZSH_HELIX_DATA_PATH
- internal/base.zsh implementa helix::internal::install y helix::internal::sync (rsync data/ → ~/.config/helix/)
- pkg/base.zsh expone helix::install, helix::sync, helix::post_install
- pkg/helper.zsh implementa helix::setup
- README.yaml + Taskfile.yml con tarea readme, registrado en Taskfile.yml raíz como module-helix
- data/ contiene config.toml, languages.toml y themes/ (configuración real de Helix)
- Usa message_*, core::exists, core::ensure (sin echo, sin which, sin command -v)
- Módulo carga: source zsh/system/core/main.zsh && source zsh/modules/helix/plugin.zsh
- Guard previene doble carga
- type helix::install y type helix::setup responden "function"

### Contexto derivado de: create-module guide

- **Three-Layer Architecture:** Every module follows `plugin.zsh → config/ → internal/ → pkg/` chain. Config exports env vars, internal has private implementation (`<name>::internal::` prefix), pkg exposes public API (`<name>::` prefix). Data/ holds rsync templates and gomplate source files.
- **Entry Point Pattern:** `plugin.zsh` uses idempotent guard (`__ZSH_<NAME>_LOADED`), resolves path with `${(%):-%x}:A:h`, sources layers in order, and gates on `$ZSH_<NAME>_ENABLED` to allow disabling modules.
- **Core Reuse Rules:** Never reimplement `message_info`/`message_success`/`message_error`, `core::exists`, `core::ensure`, or `core::install` — these come free from `zsh/system/core/`. No `echo`/`printf`, no `which`/`command -v`.
- **Naming Convention:** All env vars use `ZSH_<NAME>_` prefix. Public functions: `<name>::<verb>`. Internal functions: `<name>::internal::<verb>`. Backward-compat aliases kept as `export OLD="${NEW}"` during renames.
- **OS-Specific Files:** Always create empty placeholder `osx.zsh`/`linux.zsh` in all three layers — documents platform support, wired up for future use. Dispatch in `main.zsh` is already in place.
- **Auto-Install Pattern:** `internal/main.zsh` calls `core::ensure <dependency>` then checks `core::exists <tool>` → calls `<name>::internal::install` if missing. This runs at source time, making modules self-bootstrapping.

### Contexto derivado de: nvim reference module

- **plugin.zsh:** Uses guard `__ZSH_NVIM_LOADED`, resolves path with `${${(%):-%x}:A:h}`, shows loading message, sources config → internal → pkg in order, then runs auto-sync guards (ensures rsync, nvim, tree-sitter, hadolint are installed; auto-syncs if config dir missing).
- **config/base.zsh:** Exports `ZSH_NVIM_ENABLED`, `NVIM_CONFIG_PATH` (`~/.config/nvim`), `NVIM_PACKAGE_NAME`, `NVIM_ROOT_PATH`, `NVIM_FILE_SETTINGS`, `NVIM_DATA_HOME`, `NVIM_CACHE_HOME`, `NVIM_STATE_HOME`. Uses `: "${VAR:=default}"` pattern for safe defaults.
- **internal/base.zsh:** Implements `nvim::internal::sync` (rsync with exclude patterns for lazy/node_modules/cache), `nvim::internal::install` (sync + headless Lazy sync), `nvim::internal::upgrade`, `nvim::internal::backup` (with dry-run/apply modes), `nvim::internal::clean` (removes data/cache/state dirs).
- **pkg/base.zsh:** Thin wrappers only — each function delegates directly to `nvim::internal::<verb>` with `"$@"` passthrough. No logic in public layer.
- **pkg/helper.zsh:** `editnvim` helper opens settings file with `$EDITOR`, falls back to config dir if `NVIM_FILE_SETTINGS` unset.
- **pkg/alias.zsh:** Single alias `vim → nvim` as convenience replacement.
