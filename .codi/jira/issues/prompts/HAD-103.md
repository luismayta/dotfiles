# HAD-103: Implement Bitwarden CLI installation via native binary download in devops module

## Contenido Fuente

### Scenario

The Bitwarden CLI npm package (`@bitwarden/cli`) was hijacked in version 2026.4.0 with a malicious payload that uses Bun to steal credentials. To ensure security, we need to implement installation via native binary download instead of npm/bun. This follows the established three-layer architecture pattern (config/internal/pkg) as documented in `docs/guides/implement-tool-in-module.md`.

The binary installation method is the recommended approach by Bitwarden for production environments and avoids the security risks associated with npm package management.

### Acceptance Tests

- Create `config/bitwarden.zsh` with `DEVOPS_BITWARDEN_*` variables including download URL and binary path
- Create `internal/bitwarden.zsh` with functions: `devops::bitwarden::internal::load` (add binary to PATH), `devops::bitwarden::internal::install` (download and install binary from official URL), `devops::bitwarden::internal::upgrade` (check for updates and reinstall), `devops::bitwarden::internal::main::factory` (auto-install if missing)
- Create `pkg/bitwarden.zsh` with public API wrappers
- Register in `DEVOPS_TOOLS` array in `config/base.zsh`
- Add source lines to `config/main.zsh`, `internal/main.zsh`, and `pkg/main.zsh`
- Follow cross-platform pattern (macOS/Linux) with architecture detection (arm64/amd64)
- Use `message_info`/`message_success`/`message_error` for user feedback
- Include `core::exists` guard in load function

### Contexto derivado de: devops module structure

The devops module lives at `zsh/modules/devops/` with the standard three-layer architecture:

- `config/` — environment variables with `DEVOPS_<TOOL>_` prefix
- `internal/` — private functions prefixed `devops::<tool>::internal::`
- `pkg/` — public API functions prefixed `devops::<tool>::`

Key files for registration:
- `config/base.zsh` — contains `DEVOPS_TOOLS` array (line 11-29)
- `config/main.zsh` — aggregator for config sources
- `internal/main.zsh` — aggregator for internal sources
- `pkg/main.zsh` — aggregator for pkg sources

Existing tools: atuin, caddy, direnv, docker-compose, glab, google-cloud-cli, helm, k9s, kubectl, packer, sops, terraform-docs, terragrunt, tfenv, worktrunk, zoxide.

### Contexto derivado de: caddy reference implementation

The Caddy tool (PATH-only + native package manager pattern) is the closest reference for Bitwarden CLI:

**config/caddy.zsh:**
```zsh
export DEVOPS_CADDY_PACKAGE_NAME=caddy
export DEVOPS_CADDY_CONFIG_DIR="${HOME}/.config/caddy"
export DEVOPS_CADDY_CONFIG_FILE="${DEVOPS_CADDY_CONFIG_DIR}/Caddyfile"
export DEVOPS_CADDY_DATA_PATH="${DEVOPS_PATH}/data/caddy"
```

**internal/caddy.zsh:**
- `devops::caddy::internal::load` — core::exists guard, PATH setup
- `devops::caddy::internal::install` — core::install or custom installer
- `devops::caddy::internal::upgrade` — upgrade logic
- `devops::caddy::internal::main::factory` — core::ensure caddy
- Ends with: `devops::caddy::internal::load` + `devops::caddy::internal::main::factory`

**pkg/caddy.zsh:**
- Thin wrappers: `devops::caddy::install`, `devops::caddy::upgrade`, `devops::caddy::post_install`

### Contexto derivado de: existing bitwarden module

A separate `zsh/modules/bitwarden/` module already exists with config/internal/pkg structure. This is a standalone module, NOT the devops tool implementation. The devops tool will be a new tool within the devops module, separate from this existing module.

### Contexto derivado de: implement-tool-in-module.md guide

Full guide at `docs/guides/implement-tool-in-module.md` (601 lines). Key patterns:

- Binary download tools use `DEVOPS_<TOOL>_INSTALL_URL` and `DEVOPS_<TOOL>_BIN_PATH` variables
- Architecture detection: `$(uname -m)` returns `arm64` or `x86_64`
- Cross-platform: `case "${OSTYPE}" in darwin*|linux*)`
- Guard pattern: `if ! core::exists <tool>; then return; fi`
- Auto-install: `core::ensure <tool>` or custom install function
- Message functions: `message_info`, `message_success`, `message_error`
